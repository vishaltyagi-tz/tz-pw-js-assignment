# Writing Clean & Maintainable Test Code

**Optional Session H** · Self-paced, anytime after Week 12 · Optional · Coding Standards & Best Practices
**Session Owner:** Self-study

## Learning Objectives

Consistent naming conventions (files, functions, variables), ESLint & Prettier setup, avoiding hardcoded waits/magic strings, DRY principle in test code, meaningful assertions vs over-asserting, code review checklist for PRs, folder/file structure conventions.

## For Session Owners

- Prepare talking points and any live-demo code around the objectives above.
- Add supporting material (slides, sample code, recordings, cheat sheets) to this `Artifacts` folder.
- Review participant submissions in the sibling `../<ParticipantName>/` folders after the session.

## Weekly Assignment (Homework)

1) Install and configure ESLint + Prettier in your Playwright project, fix all existing lint warnings across previous weeks' scripts.

2) Refactor one existing test file to remove magic strings/hardcoded values into a constants or config file, and rename any poorly-named variables/functions.

3) Create a short personal 'Code Review Checklist' (5-8 items, e.g. no hardcoded waits, descriptive test names, no duplicated locators) and apply it to review one of your own past assignments, noting what you'd change.

## Submission Instructions

- Save your files inside `Sessions/Optional-H-Coding-Standards-Best-Practices/<YourName>/` (your own participant folder).
- Use plain, descriptive filenames as instructed above.
- Do not commit `node_modules/` or other generated folders.
