# Optional E — DevTools → Playwright Translation Guide

Companion to `Session-Guide.md`. The point of this session: **if you can't select
it in the DevTools Console, Playwright won't find it either.** Debug there first —
it's a two-second loop instead of a thirty-second test run.

## Opening DevTools

| Action | Mac | Windows |
|---|---|---|
| Open DevTools | `Cmd + Option + I` | `F12` |
| Inspect an element | `Cmd + Shift + C` | `Ctrl + Shift + C` |
| Console | `Cmd + Option + J` | `Ctrl + Shift + J` |

## Console selector cheatsheet

```js
document.querySelector('#login-button')          // first match, or null
document.querySelectorAll('.inventory_item')     // all matches (a NodeList)
document.querySelectorAll('.inventory_item').length   // how many? ← ask this always
$('#login-button')                               // DevTools shorthand for querySelector
$$('.inventory_item')                            // shorthand for querySelectorAll
$0                                               // the element currently selected in Elements
```

**Always check the count.** A selector matching 12 things is a strict-mode
violation waiting to happen in Playwright.

## CSS selector syntax

| Selector | Matches |
|---|---|
| `#id` | one element by id |
| `.class` | every element with that class |
| `[data-test="login"]` | by attribute value |
| `[data-test^="add-to"]` | attribute starts with |
| `div.card > button` | direct child |
| `div.card button` | any descendant |
| `li:nth-child(3)` | third child — **avoid**, breaks on reorder |
| `input[type="checkbox"]:checked` | by state |

## The translation table

This is the sheet worth keeping:

| DevTools / CSS | Playwright | Notes |
|---|---|---|
| `$('#user-name')` | `page.locator('#user-name')` | Direct equivalent |
| `$('[data-test="login"]')` | `page.getByTestId('login')` | Set `testIdAttribute: 'data-test'` in config |
| `$('button')` by its text | `page.getByRole('button', { name: 'Login' })` | **Preferred** — matches what the user sees |
| `$('label')` then its input | `page.getByLabel('Username')` | Handles the label→input link for you |
| `$('input[placeholder="Username"]')` | `page.getByPlaceholder('Username')` | Clearer |
| Searching text by eye | `page.getByText('Products')` | |
| `$$('.item')[2]` | `page.locator('.item').nth(2)` | Works, but prefer `.filter({ hasText })` |
| `$$('.item').length` | `await page.locator('.item').count()` | Or assert `toHaveCount(n)` |

## The accessibility tree

`getByRole` doesn't read your HTML — it reads the **accessibility tree**. In the
Elements panel, open the **Accessibility** sidebar to see the role and accessible
name Playwright will use. If a button shows no accessible name there,
`getByRole('button', { name: '...' })` can't find it — and that's a real
accessibility bug worth reporting, not just a test problem.

## Selectors that will betray you

| Don't | Why |
|---|---|
| `.css-1x2y3z`, `.sc-bdVaJa` | Generated by CSS-in-JS; changes every build |
| DevTools "Copy selector" output | Produces `body > div:nth-child(3) > div > button` — breaks on any layout change |
| `:nth-child(4)` as a final answer | Breaks the moment anything is reordered or inserted |
| Deep descendant chains | Couples your test to the whole page structure |

Right-click → Copy → **Copy selector** is the trap. It always produces something
that works right now and breaks next sprint.

## Why an element "isn't there"

Before assuming Playwright is wrong, check:

1. **In an iframe?** `document.querySelector` from the top frame can't reach in. You need `frameLocator()` (Optional F).
2. **In a shadow root?** CSS can't pierce it; Playwright's locators mostly can.
3. **Not rendered yet?** The Elements panel shows the live DOM, so it may have appeared after your test looked.
4. **Rendered but hidden?** `display: none` or zero-size means "not visible" to Playwright.
5. **Covered by something?** A cookie banner or modal intercepts the click. The trace's DOM snapshot shows this instantly.
